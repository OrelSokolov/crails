# 101-ar-crud — CRails vs Rails 8: `POST /posts` (Iteration 2)

Дата: 2026-10-02. План: `../../PLAN.md` (Iteration 2), `../PLAN.md` (write-сценарий).

## Окружение

- То же, что в `100-ar-read.md`: один PG 17, БД `crails_bench`, пул 16,
  wrk (4 threads), warmup, 3 прогона по 10 s → медиана.
- Логика идентична: `Post.create(title: "bench-<ts>", views: 0)` — модель
  с валидациями (presence, length ≤ 140) → INSERT; тело запроса обе
  стороны генерируют title сами (server-side).
- Запросы JSON (`Content-Type: application/json`), см. примечания.

## Результаты

| Метрика | CRails | Rails 8 + Puma (t16) |
|---|---|---|
| RPS записи, c=10 (медиана) | **1 879** | 406 |
| RPS записи, c=100 (медиана) | **3 747** | 433 |
| Ошибок (non-2xx / timeout) | 0 / 0 | 0 / 0 |
| RSS после нагрузки | ~21 MB | ~120 MB |

Полные прогоны (RPS):
- CRails c10 = 1877 / 1882 / 1879; c100 = 3790 / 3747 / 3733
- Rails t16 c10 = 410 / 395 / 406; c100 = 433 / 433 / 438

Контроль вставок по счётчику таблицы: 195 035 строк за 6 прогонов —
совпадает с суммой запросов wrk, потерь нет. После замера bench-строки
удалены, таблица возвращена к 1 000 сидам.

## Вывод одной строкой

CRails пишет в PostgreSQL ~**4.6×** RPS Rails 8 (1.9k vs 406 при c=10;
3.7k vs 433 при c=100) при ~**6×** меньшей памяти; потолок обоих —
fsync-коммит WAL локального PG, поэтому разрыв меньше, чем в чтении.

## Примечания честности

- CSRF: Rails из коробки отвергает не-GET без токена (422, включая
  JSON). Чтобы мерить путь INSERT, а не forgery-protection, в бенч-
  контроллере Rails добавлено `skip_before_action
  :verify_authenticity_token, only: :create`. У CRails CSRF-слоя пока
  нет вовсе — сравнение логики записи, а не защиты.
- Первый прогон с form-encoded POST у Rails показал «313 RPS» — это
  были 100% 422 без единого INSERT; в зачёт не идёт.
- INSERT одной строки с коммитом — узкое место сам PG (group commit),
  поэтому c=100 у обоих выше c=10: БД группирует fsync.
