# 205 — active_backup: backup/restore throughput

Setup: CRails `ActiveBackup` (Iteration 14, P0), Crystal 1.21 release
build. PostgreSQL 16.9 (unix socket), pg_dump/pg_restore 16.9
(pinned под мажор сервера). Данные: таблица 200 000 строк × ~200 Б
(pg_dump -Fc ≈ 12 МБ) + 100 файлов × 1 MiB случайных байт (104.9 МБ
сырых). Все операции — один поток, локальная машина.

Запуск: `bench/crails_backup/bin/bench [ROWS] [FILES]` (сборка:
`crystal build --release -o bin/bench bench.cr` из каталога бенча;
фреймворк-шарды — lib/-симлинки).

## Результаты (2006-10-06, rows=200000, files=100×1MiB)

| Операция | Время |
|---|---|
| seed 200k строк (~40 МБ данных) | 0.76 s |
| seed 100 × 1 MiB файлов | 0.34 s |
| **create** (pg_dump + ustar+gzip ~117 МБ сырья → 109.4 МБ архив) | **2.98 s** |
| **restore** (sha256-verify всех членов + pg_restore + файлы) | **1.04 s** |
| ref: системный `tar czf` только файлы (104.9 МБ) | 2.83 s |

Проверка целостности после restore: 200 000/200 000 строк, файлы
побайтово (см. spec/restore_spec.cr — тот же флоу в CI).

## Выводы

- **Тар-писатель в паритете с GNU tar**: наш ustar+gzip контейнер на
  104.9 МБ случайных байт — 2.83 s у системы против 2.98 s у нас за
  полный create (который включает ещё pg_dump 40 МБ БД и sha256 всех
  членов). Gzip (DEFLATE) доминирует в обоих случаях; случайные байты
  не сжимаются, архив ≈ размеру сырья минус заголовки.
- **Restore быстрее create**: gzip-распаковка дешевле сжатия, а
  pg_restore льёт COPY-поток. 1.04 s для полного восстановления
  БД+файлов с проверкой контрольных сумм — disaster recovery
  веб-приложения укладывается в секунды.
- Retention/prune — O(N) по листингу стора, в бенче не значимы.
- Пропускная способность полезной нагрузки: ~39 МБ/s create,
  ~112 МБ/s restore на одной ноде; для прод-масштабов (ГБ) бэкап —
  фоновая recurring-джоба (ActiveJob), не веб-путь.

## Скейлинг

Пропорционально объёму (стриминговая запись в один проход, память
константна — буфер 64 КиБ; sha256 стриминговый). Инкрементальные
бэкапы и шифрование — P2 (см. active_backup.cr/PLAN.md).
