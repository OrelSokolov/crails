# ECOSYSTEM.md — экосистема CRails (Фаза 3, после порта и модернизации)

> Позиционирование: не «ещё один фреймворк», а **самый быстрый
> time-to-market на высокопроизводительном монолите**. Дух DHH
> «блог за 15 минут» (2005) → «AI SaaS за день» (2026).

## 1. Что говорит рынок (октябрь 2026)

- **Усталость от сложности Next.js.** Использование ~59–60%, но
  удовлетворённость упала 68%→55% — крупнейший провал в истории
  State of JS 2025. Разрыв с Astro (№1 по удовлетворённости) — 39 п.п.
  Вывод: рынок хочет **простоту**, но не ценой производительности.
- **AI-MVP 2026 собирают из готовых API:** Supabase/Clerk (auth) +
  Stripe (billing) + Resend (email) + Postgres + LLM API. Стартапер
  платит деньгy и временем за склейку trivia (auth, письма, очередь).
  Всё это trivia уже внутри монолита: devise.cr, action_mailer.cr,
  active_job.cr, AR+PG.
- **Rails уходит в Solid-стек** (очереди/кэш/pubsub на PG) — мы
  делаем так же по умолчанию (старт на одном PG), но без фанатизма:
  **Redis — штатная опция через адаптеры**, включается конфигом когда
  нужен. В остальном Rails подтверждает курс: Local CI, надёжные
  джобы, Lexxy из коробки.
- **Server-driven UI** (LiveView/Hotwire) — стандарт для B2B SaaS.
- **AI-кодоген меняет требования к фреймворкам:** LLM лучше пишут
  предсказуемый, декларативный, типизированный код с контрактами,
  чем_configuration-ад. Статическая типизация + OpenAPI codegen
  (Iteration 10) = фреймворк, дружелюбный к AI-генерации кода.

## 2. Наше оружие (почему Crystal-монолит)

1. **142k RPS / 16 MB RSS / старт 10 мс** (bench 000-hello) —
   вертикальное масштабирование: один дешёвый VPS держит первых
   клиентов. Не нужен K8s, не нужен Vercel.
2. **Fiber'ы** — конкурентность почти бесплатно: WebSocket на каждого
   пользователя, стриминг ответов, фоновые задачи. Без Kafka и
   микросервисов; на старте вообще один PG, Redis — опция.
3. **Один бинарник** — деплой = scp + миграции.
4. **C-биндинги** — libvips и любые нативные либы без прослоек.
5. **Статическая типизация** — контракты, а не тесты на коленке.

## 3. Бутстрапы — сердце экосистемы

Дух DHH-демо «Twitter за 15 минут»: каждое направление —
`crails new <app> -b <bootstrap>` с готовым скелетом.

| Bootstrap | Что внутри | Для кого |
|---|---|---|
| `b2b-saas` | auth (devise.cr), billing (Stripe), админка, письма, multi-tenant | классический SaaS, время-to-market 1–2 дня |
| `ai-app` | LLM chat UI с токен-стримингом (Iteration 9), биллинг по токенам, очередь агентов (active_job), RAG на pgvector | AI-обёртки, агенты — самый горячий сегмент 2026 |
| `api-only` | OpenAPI из типов (Iteration 10) + генерация TS-клиента | фронт на Next/React/Swift нам не конкурент |
| `realtime` | LiveView (Iteration 8) + presence + лента | соцсети, дашборды, чаты |
| `media` | HLS/стриминг на fiber'ах, ActiveStorage | видеосервис без Kafka и микросервисов |
| `marketplace` | двухсторонний маркетплейс: платежи, поиск (pg full-text/trgm) | e-com MVP |

**Метрика каждого бутстрапа: время от `crails new` до задеплоенного
приложения.** Цель — день для одного разработчика. Это и есть
главный продающий демо-контент (дух DHH-видео).

## 4. Где обгоняем Next.js (и где честно не гонимся)

**Обгоняем:**
- Простота: один язык, один бинарник, ноль конфигурации против
  Server Components/RSC/конфиг-ада — ровно в болевую точку падения
  удовлетворённости.
- Realtime: ws в монолите, у Next — отдельные сервисы и костыли.
- LLM-стриминг: first-token latency, дешёвые fiber'ы, backpressure.
- TCO: без Vercel lock-in, без Node-зоопарка, RSS в ~7 раз меньше.
- AI-кодоген: типизированные декларативные API + OpenAPI-контракты
  генерятся LLM заметно лучше, чем Next.js-конфигурации.
- Self-hosting из коробки: `crails deploy` = scp бинаря.

**Честно не гонимся:** npm-экосистема, SSR React, edge-рантаймы,
маркетинговые бюджеты Vercel. Стратегия: UI — это HTML (+TS где надо,
через `api-only`-режим или LiveView); бэкенд и фронтенд можно
делить — одно другому не мешает. Next.js-фронт поверх CRails-API —
легитимная связка, а не капитуляция.

## 5. Монетизация: лестница (цель — не работать в такси)

> Принцип: фреймворк бесплатный навсегда. Деньги — на слоях НАД ним.
> Покупатель бутстрапа платит за сэкономленную неделю, а не за язык.

### Ступень 0 — гранты (деньги уже сейчас, до релиза)
- **NLnet Foundation** — открыты для open-source заявок, раунды ~2 раза
  в год, €5–50k. Тема «открытый высокопроизводительный веб-фреймворк» —
  проходная. Проверить ближайший дедлайн на nlnet.nl/funding.
- **Sovereign Tech Fund** — дословно инвестируют в «библиотеки для
  языков программирования, package managers, открытую инфраструктуру».
- GitHub Sponsors / Open Collective — подключить сразу после первого
  вирусного поста (не раньше, пустая страница отпугивает).

### Ступень 1 — бутстрапы как продукты («лопаты»)
Модель Marc Lou (ShipFast: >$1M суммарно) / Tailwind UI / Laravel Spark:
- Скелет `crails new` — **бесплатно** (это маркетинг фреймворка).
- Полный бутстрап (`ai-app` с токен-биллингом, `b2b-saas` со Stripe
  и админкой) — **$99–299 one-time** с обновлениями на major-версии.
  $10 не окупают даже support.
- Уроки ShipFast: (1) это НЕ пассивный доход — падение с $125k/мес
  до ~$3.5k/мес без постоянных запусков; (2) аудиторию строят
  запусками на HN/Reddit, трамплин — наши бенчи (000-hello);
  (3) продал — патчишь и закрываешь дыры, иначе публичный скандал.

### Ступень 2 — SaaS-инструменты (рекуррентные деньги)
Аналог Laravel Forge/Cloud: панель деплоя и мониторинга CRails-приложений
(scp бинаря + миграции + healthz уже в ядре — надо только UI).
Подписка $10–20/мес. Возможно только после появления чужих приложений.

### Ступень 3 — контент и услуги
Курс «AI SaaS за день на CRails», консалтинг для ранних адаптеров.
Появляется сам, когда есть аудитория; не тратить силы раньше времени.

### Порядок действий
1. NLnet-заявка до ближайшего дедлайда (час работы, шанс денег
   независимо от хайпа).
2. Довести Iteration 1–2 → HN-пост с бенчами (момент правды).
3. Бутстрапы — после Iteration 8–11, когда `ai-app` демо-способен.
4. SaaS-панель — только когда есть пользователи, не раньше.

## 6. Scaling story: монолит до миллиона клиентов (без микросервисов)

> Что продаём: «1M пользователей = 1–3 сервера + Postgres (Redis —
> опция, не требование). Без Kafka, без K8s, без микросервисов.»
> И доказываем это бенчем, а не слоганом.

### Почему монолит масштабируется
- HTTP-часть **stateless**: сессии в cookie/PG → N бинарников за
  любым round-robin LB, sticky sessions для веба не нужны.
- WebSocket/LiveView: соединение физически живёт на одной ноде (TCP
  пинит сам), pubsub между нодами — PG `LISTEN/NOTIFY` по умолчанию
  или Redis-адаптер. Нода умерла → клиент переподключился к живой
  (схема Phoenix, проверена годами).
- Очередь — адаптеры: PG по умолчанию, Redis (Sidekiq-модель) опцией.
  В обоих случаях воркеры на любых нодах: добавил нод = добавил
  мощности.
- **Брокер (RabbitMQ/Kafka) — НЕ инструмент масштабирования**, а
  adapter в ActiveJob для интеграции с внешним миром (аналитика,
  партнёры). Подключается по необходимости, никогда не требуется.

### Математика миллиона (обязательство проверить бенчем)
1M зарегистрированных ≈ 1–5% одновременно = 10–50k живых соединений,
100–500 RPS в среднем, пики — единицы тысяч RPS. При 142k RPS hello
(bench 000) и консервативных 10–20k RPS реальных AR-запросов:
**1M клиентов = 1–3 сервера + PG.**
Обязательство: bench `1m-load` (синтетика с реалистичным миксом:
лента/чтение/запись/ws) опубликован в `bench/results/` — часть
продукта, а не маркетинга.

### Инструменты масштабирования в комплекте
- `crails worker` — воркер-режим того же бинарника (очередь, стриминг,
  recurring jobs).
- `crails scale` — генерирует systemd/compose: N web + M worker
  процессов на машине, конфиг одной командой.

## 7. WordPress-режим: «власть пользователю» (Фаза 3, строго после порта)

> Дух 2010-го: установил движок — получил контроль без кода.
> Наша версия: купил lifetime → `scp` бинаря → `crails setup` → работает.

- **Модули галочками на этапе сборки** — compile-time registry (принцип
  №2 PLAN.md), идеально ложится на Crystal:
  `crails new site --with admin,storage,comments,shop`.
- **`crails setup`** — интерактивный мастер: БД, модули, ключи Stripe/
  SMTP, миграции, первый пользователь-админ. Ноль конфигов руками.
- **Мастер установки — отдельный шард `crails-wizard`**: интерактивно
  выбираешь направление/бутстрап/модули → указываешь SSH-ключ сервера
  → wizard собирает бинарь с нужными модулями и деплоит сам. Человек
  без знания внутренностей получает работающий продукт на своём
  сервере — «власть как в WordPress 2010».
- **Встроенная админка** — CRUD из `schema.yml` без кода (аналог
  ActiveAdmin), включая настройку модулей.
- **Бэкапы из админки** — Active Backup (Iteration 14): куда, как
  часто, retention — чекбоксами, без консоли.
- ⚠️ Это отдельный продукт (дистрибутив) поверх фреймворка. Не начинать
  до завершения Фазы 1–2, иначе не будет ни того, ни другого.

## 8. Adoption: маховик (как это распространяется)

> Механика WordPress/PHP, а не «новый язык победит качеством»:
> ставится легко → что-то работает → нужны руки → появляются
> программисты с работой. Маховик крутит работающий продукт.

0. **Seed: бенчи + «framework extracted from real product».**
   HN-пост с цифрами (hello → 1m-load), и как можно раньше — реальный
   продукт на CRails (форум-движок / Cockpit). Комьюнити верит
   фреймворкам, извлечённым из работающих продуктов (Basecamp → Rails).
1. **Девы пробуют** — API 1:1 → нулевая кривая для Rails-мигрантов,
   LLM уже «знают» CRails в день релиза (обучены на Rails-коде):
   генерация кода с нулевым выстрелом. Ни один новый фреймворк
   такого не имел.
2. **Инди шипят продукты на бутстрапах** → страница «built with
   CRails» → социальное доказательство.
3. **Не-программисты ставят через wizard/Cockpit** → им нужна
   кастомизация → **спрос на руки** (начало петли пользователя).
   Быстрее найма крутится маркетплейс тем/модулей: фрилансеры
   зарабатывают на кастомизации установок (экономика WordPress).
4. **Рынок найма** — самая медленная стадия (у Node заняла ~5 лет).
   Не форсировать, придёт само.

**Правила выживания маховика:**
- Удерживает второй день: docs/cookbook и читаемые error pages
  (Iteration 13) — часть дистрибуции, не роскошь.
- Каждый вау — шарящийся артефакт: гифка «crails new → работающий
  магазин за 3 минуты».
- Одно «оно съело мои данные» убивает больше доверия, чем сто
  бенчмарков создают: тесты 1:1 (AGENTS.md) и Active Backup с
  restore-тестом в CI — условие выживания.
- Без VC (Elixir получал деньги только через компании): гранты +
  выручка бутстрапов/лицензий + marketplace. Медленный рост —
  не приговор, а отсутствие дедлайна гиперроста.

## 9. Критерии успеха экосистемы

- Время `crails new` → деплой: ≤ 1 дня на бутстрап (цель).
- Число внешних сервисов для MVP: **0** (монолит всё заменяет;
  платные API — только Stripe и LLM по необходимости).
- RPS/RSS бутстрап-приложений — в `bench/`, против эквивалента
  на Next.js/Node.
- Сколько строк кристалла написал разработчик для MVP —
  чем меньше, тем лучше (генераторы + AI-кодоген по контрактам).
