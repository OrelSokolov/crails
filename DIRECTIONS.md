# DIRECTIONS.md — топ-30 направлений для CRails: где монолит забирает рынок

> Зачем: клиент скачивает фреймворк, когда видит, что в нём ЕСТЬ всё
> для ЕГО направления. 30 направлений = 30 готовых конфигураций
> мастера установки (`crails-wizard`).
>
> Архитектура везде одна: **монолит + PG** (данные, а по умолчанию
> ещё очередь/кэш/pubsub), **Redis — штатная опция** через адаптеры.
> Никакой нарезки на микросервисы. Это и есть расчёт «на бумаге»
> под типичный кейс каждого направления.

## Общая математика на 1M клиентов

- 1M зарегистрированных ≈ 1–5% одновременно живых = 10–50k активных,
  100–500 RPS в среднем, пики 1–5k RPS.
- Одна веб-нода CRails (консервативно): 10–20k RPS реальных
  AR-запросов, цель 100k ws-соединений (PLAN, Iteration 4/8).
- Вывод: CRUD/контент-направления = 1–3 веб-ноды + 1 PG + 1 Redis ≈
  **$80–200/мес за 1M клиентов**. Realtime- и полоса-тяжёлые — честно
  дороже, цифры в таблицах. Точный потолок каждой конфигурации
  фиксируется бенчем `1m-load` (ECOSYSTEM.md §6).

Рыночная опора (трекеры micro-SaaS, 2026): самые маржинальные
категории — community tools (~80%), developer tools (~74%),
AI ops (70–85%). Агентства и фрилансеры — самые надёжные покупатели
B2B SaaS: платят $50–300/мес без разговоров. Соц-коммерция —
быстрорастущий сегмент e-com.

## Ключевой инженерный вывод

30 из 30 направлений закрываются **уже запланированной архитектурой**,
новых подсистем не нужно. Что оказывается критичным почти везде:

1. **Recurring jobs** (#3, 6, 16, 17, 19, 22, 26) — подтверждение
   Iteration 7: без cron'а в очереди нет ни dunning, ни SLA, ни
   напоминаний. Это самая «продающая» невидимая фича.
2. **Встроенная админка** (#16–18, 23, 27) — CRUD из schema.yml без
   кода: половина B2B-направлений — это «админка как продукт».
3. **Очередь + воркеры** (#2, 8, 10, 12, 25, 28) — любой фон,
   транскод, fan-out, матчинг.
4. **Cable/Redis pubsub** (#11–15, 28, 30) — всё живое.
5. **SSE-стриминг** (#8, 24) — видео и LLM.

Каждое направление после Iteration 8–11 превращается в конфигурацию
`crails-wizard`: чекбоксы модулей → бинарь → SSH-ключ сервера →
деплой. Мастер установки — отдельный шард, см. ECOSYSTEM.md §7.

## G. egui.cr × CRails: десктоп + веб в одном языке (вытеснение двух-стековых команд)

> У нас есть egui.cr (~/egui.cr): нативный UI на чистом Crystal
> (reactive + immediate mode, CSS-cascade, свои FreeType/NanoSVG,
> sokol GPU, mac/win/linux). Связка с CRails = один язык на всех
> поверхностях продукта: shared-модели, валидация, типизированный
> API-клиент из OpenAPI-кодгена (Iteration 10). Ниша: вертикальный
> B2B, где софт = десктоп-станция сотрудника + веб-кабинет владельца.
> Сейчас такую нишу делают двумя командами (C#/Qt + Rails/Node) —
> мы закрываем одним разработчиком и двумя бинарями.

| Продукт | Десктоп (egui.cr) | Веб (CRails) | Кого вытесняем |
|---|---|---|---|
| SCADA/HMI, промпанели | станция оператора, GPU-графики телеметрии (Modbus/OPC-UA через C) | сбор телеметрии, история, алерты | C++/Qt, проприетарщина 2000-х |
| Автодиагностика/дилеры | терминал механика (OBD-II/SocketCAN через C) | ремонты, клиенты, запчасти (#16) | древний дилерский софт |
| POS/розница | касса: фискальники, сканеры, offline-first | товары, отчёты, e-com витрина | C#, Electron, 1С |
| Клиники/стоматологии | ресепшн, сканеры документов | веб-запись пациентов (#19) | двух-стековые команды |
| NVR/умный дом, пульты | пульт охраны, видео через C-декодеры | телеметрия, админка (#27) | проприетарные пульты |
| Offline-first полевой софт | локальный SQLite + синк | бэкенд, диспетчерская | C#/.NET |
| Трейдинг-терминалы | ws-стрим, нативные графики | стриминг-бэкенд | Electron (в 100 раз тяжелее) |
| **CRails Cockpit (dogfood)** | панель управления деплоями: логи, очереди, деплой, wizard | сам деплой (api) | Laravel Forge (веб-only) |

Первое приложение связки — **CRails Cockpit**: рабочий демо-кейс
обоих фреймворков и бесплатный маркетинг. Не лезть: чат, почта, VPN,
Slack-клоны — Electron-категории без системной составляющей.

## Приоритизация: где деньги × где вход быстрее × КТО заплатит

> Мы не вытесняем C++-ников — они не пересядут. Наш покупатель — тот,
> кому C++/Qt недоступен в принципе: веб-разработчик, которому нужна
> системная производительность без системного программиста.
> Сортировка по персоне покупателя, а не по нише.

### Персоны (кто готов вложить 2 дня и получить результат)

1. **Rails-разработчик / агентство** — главный покупатель. Наш API
   1:1 (принцип PLAN.md №1) → кривая обучения нулевая, а хостинг в
   разы дешевле и запас масштабирования огромный. Инвестиция «2 дня»
   для него буквально: знакомый синтаксис, знакомые тесты (RSpec-дух),
   консоль, генераторы — всё как дома, только компилятор ловит ошибки
   вместо прогонов тестов.
2. **Инди-хакер (категория Marc Lou)** — хочет SaaS за уикенд, не
   хочет Node-зоопарк и Vercel-счёта. Покупает бутстрап за $199.
3. **Основатель вертикального SaaS (HVAC, клиники, RV-парки)** —
   умеет писать на Ruby/PHP-уровне, C++ для него не вариант вообще.
   Ему нужен CRUD + recurring + Stripe за 2 дня.
4. **Команда 10–15 человек с Rails-легаси** — растущие счета за
   инфраструктуру: тот же код, в 10 раз меньше серверов.

### Tier 1 — деньги сразу, вход 2 дня (закрыт Фазой 1, чистый CRUD + recurring + Stripe)

Job board (#20), инвойсинг (#22), internal tools/админки (#18),
нишевая CRM (#16), client portal (#23), AI-чат SaaS (#24).
Это направления, где результат виден за день-два, и где B2B-клиенты
платят $50–300/мес без разговоров. **Здесь начинаем.**

### Tier 2 — деньги есть, вход после Фазы 2 (нужны LiveView/стриминг/Cable)

Магазин (#1), маркетплейс (#2), LMS (#7), booking (#19), helpdesk
(#17), livechat (#15), форум (#11), комьюнити/чат (#12–13), dating
(#28), аналитика (#10). Bootstraps из ECOSYSTEM.md §3.

### Tier 3 — большие деньги, длинный вход (C-обвязки, B2B-продажи, egui.cr-зрелость)

## H. Аудитория «vibe-кодеры / менеджеры»: движок как продукт

> Персона: не-программист (или barely-программист) с $100–200
> лишних денег, который хочет запустить СВОЙ продукт. Для него
> «работает из коробки» = не видеть терминал вообще.

### Путь пользователя
1. Скачал **CRails Cockpit** (нативное egui.cr-приложение).
2. Описал сайт словами («сайт студии: портфолио, прайс, запись,
   оплата») → AI-мастер выбрал модули, сгенерил страницы, собрал
   бинарь с галочками.
3. Указал SSH-ключ сервера → деплой → работает. Админка как в
   WordPress: контент, модули, бэкапы (Iteration 14) — чекбоксами.
4. PWA из коробки (Iteration 8): сайт клиента ставится на телефон
   как приложение — без App Store и без $99/год. Для этой аудитории
   это магия уровня «у меня есть своё приложение».

Это «WordPress-2010 власть» (поставил движок → получил контроль),
усиленное AI-эпохой: вместо формы установки — описание словами.

### Монетизация этой аудитории
- Лицензия $199 lifetime (готовый движок + wizard).
- **Маркетплейс тем и модулей** — экономика WordPress-мира держалась
  на темах; тема у нас = CSS + ECR-шаблоны (просится к CSS-каскаду).
  Revenue share с авторов тем → экосистема растёт без нас.

### Мультитенанси — честный вердикт
- Этой аудитории он не нужен: их продукт single-tenant по
  определению.
- 16 MB RSS + деплой scp = инстанс-на-клиента на $5 VPS дешевле,
  чем один мульти-тенантный монстр → половина классических причин
  отпадает.
- Что делаем: (1) конвенция `tenant_id` в кодогене schema (Iteration 2,
  ноль стоимости), (2) модуль `--with multitenant` в Фазе 3 — для
  тех, кто строит платформу для чужих организаций (Shopify-подобные).
  В ядро не вшиваем.

## I. Свободный интернет: блог и платные коммьюнити (куда двигаться)

> Знание в мессенджерах испаряется (не индексируется, каналы
> исчезают). Структура «вопрос → ответ → пермалинк → индексация» —
> единственный механизм консервации экспертизы. Носитель потерян,
> механизм жив.

### Механизм ухода из мессенджера
Участника из TG не выманить ничем — и не надо. **Люди ходят за
лидером, а не за платформой.** Продаём владельцу: TG = воронка
(бесплатно, все там), своя платформа = дом (деньги, знание,
владение). Участники переходят за закрытым контентом и сообществом.

### Два продукта
1. **Блог-движок — семечко экосистемы** (как WordPress начинался
   блогом): публикация → джоба рендерит статический HTML → отдача
   с кэша; живые комментарии через Cable; бэкапы встроены; PWA.
   $5 VPS + бинарь + свой домен + свой мейл-лист. Дешевле Ghost
   ($9–199/мес за хостинг того же).
2. **Платное коммьюнити-движок (формула Skool)** — форум-структура
   (знание) + чат (Cable) + курсы (LMS) + подписки (Stripe).
   Рынок платных комьюнити растёт, community tools — №1 по марже
   (~80%, наш research). Skool берёт $99/мес — мы на своём $5.

### Эпоха AI: парадокс
Публичный SEO-форум общего назначения слабее 2010 (LLM отвечают на
generic-вопросы). Но следствие обратное: свежее человеческое знание
дороже — модели обучены на старом, люди обсуждают новое в закрытых
сообществах. Ставка — закрытое/платное/свежее, не публичный Q&A.

### PWA → приложение
Android: PWA оборачивается в Play Store APK через TWA — генерится из
того же кодегена роутов. iOS: только home-screen PWA или
WebView-оболочка (аналога TWA нет). Слоган: «сайт = сразу
приложение на Android, на iOS — в один тап».

## J. Финтех: где монолит на CRails уместен

> Три финтеховые боли, в которые бьём: предсказуемая латентность,
> строгие контракты, аудит. Ядро — не Kafka, а PG с ACID:
> ledger двойной записи = append-only проводки + балансы-проекция.
> Деньги — Int64/Decimal, никогда float; типизация — требование,
> а не бонус (ошибка не компилируется, а не находится в проде).

Уже запланировано и финтеховое: recurring jobs (dunning, списания,
отчёты регулятору), idempotent-вебхуки PSP (дедупликация + очередь —
80% интеграционного кода), OpenAPI-кодген (контракты для партнёров/
BaaS/регуляторов), OTel («где деньги» = трейс), Active Backup,
один бинарь = малая поверхность атаки и воспроизводимая сборка.

Ниши: BaaS-обёртки (необанк для ниши поверх лицензированного
партнёра — app-слой это наш Tier 1) · биллинг/подписки (#22) ·
split-платежи/escrow маркетплейсов (#2) · крипто-бэкенды (кошельки,
стейблкоин-процессинг; secp256k1/ed25519 через C-биндинги) ·
персональные финансы (open banking + категоризация).

Бессилен (не пытаться): HFT/биржевые ядра (C++/FPGA), core banking
банковского масштаба, PCI-DSS — карточные данные только токенизированно
через PSP, мы их не касаемся никогда.
